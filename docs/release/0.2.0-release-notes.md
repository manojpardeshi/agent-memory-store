# LLM Memory Store 0.2.0

LLM Memory Store 0.2.0 makes recall faster, adds metadata lookup and an opt-in hybrid recall mode,
and publishes the project's first measured comparisons with other memory systems. Default recall
results are unchanged.

## Highlights

- **Faster recall.** `recall` now scores candidates from one batched query and loads only the
  records it returns: about 6 SQL statements per call instead of about 123 at limit 10, with
  median latency roughly halved. Results are identical, verified against the previous algorithm.
  Listing and JSON export also fetch records in batches.
- **Metadata lookup.** `MemoryStore.find_by_metadata(scope, filters)` returns memories in one exact
  scope whose metadata matches every filter, matched inside SQLite.
- **Opt-in hybrid recall.** `retrieval="hybrid"` (Python), `--retrieval hybrid` (CLI), and
  `retrieval: "hybrid"` (MCP) fuse vector ranking with an FTS5 keyword ranking. Use it when
  queries quote names, codes, or numbers from the memory. Vector stays the default because hybrid
  lowers ranking quality for questions that share no words with their answer.
- **Experimental date resolution.** `llm_memory_store.temporal.resolve_event_dates` turns relative
  English dates ("last Tuesday", "3 weeks ago") into calendar dates deterministically. Recall does
  not use it yet.

## Compatibility

- `SCHEMA_VERSION` stays 1, and no stored data is rewritten.
- The first time 0.2 opens a store writable, it adds a keyword index (`memory_keywords`) and three
  triggers that keep it in sync, then backfills the index once.
- A 0.1 runtime can keep reading and writing an upgraded store when its SQLite is 3.44 or newer.
  Release verification tested 0.1.0 from PyPI against a 0.2-upgraded store.
- The keyword index uses FTS5 secure-delete, so `forget` and expiry purge physically remove a
  memory's words from it. On SQLite older than 3.44 the index is not created and hybrid recall is
  unavailable; everything else works as before.

## Measured evidence

Under free local models on a balanced thirty LongMemEval-S questions, the store's top ten
contained the gold answer text in 18 cases against 8 for Supermemory Local 0.0.8, using less than
half the context. Every question one system found and the other missed went to the store (sign
test p = 0.002). On 180 development questions with a paid answerer and judge, the store scored
134 against 93 for Mem0's hosted Hobby tier. Both comparisons, their protocols frozen before the
runs, and their limits are documented under `docs/architecture/benchmarks/`. Several candidate
changes that failed their pre-registered gates were recorded and kept out of the product.
