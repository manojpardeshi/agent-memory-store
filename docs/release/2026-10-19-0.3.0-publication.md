## Pre-publication gate

`scripts/verify_release.py` passed on the release commit at the first attempt: clean `main`, lock,
pytest, Ruff, dashboard lint and rendered-HTML test, production dashboard audit, pip-audit, two
byte-identical builds, Twine check, and Gitleaks over the tree, full history, and artifacts. No new
runtime advisory appeared since 0.2.0. The demo dashboard's development-tool findings are unchanged
from the 0.2.0 record.

## Release verification

- A clean install of the built wheel completed an offline lifecycle on CPython 3.11.15, 3.12.11,
  3.13.3, and 3.14.5. The lifecycle covered:
  - remember with `occurred_at`, stored in UTC and shown in the context header;
  - hybrid recall and metadata lookup;
  - verified forget, then keyword index `ok` and integrity `ok`.
- `llm-memory --help` succeeded on each version, and `llm-memory-mcp` started and exited cleanly on
  end of input.
- Stores created by `llm-memory-store` 0.1.0 and 0.2.0 from PyPI were opened by 0.3.0. Each gained
  the `occurred_at` column and the keyword index, with integrity `ok`.
- Before release, 0.1.0 and 0.2.0 were shown to keep writing, correcting, recalling, and
  forgetting in a 0.3-upgraded store. Corrections they make do not carry `occurred_at` forward.
- A fresh clone of the public GitHub tag rebuilt a byte-identical wheel and source archive.
