## Pre-publication gate

The first gate run failed pip-audit:

- Pillow 12.3.0 had about 40 advisories, fixed in 13.0.0.
- filelock 3.29.7 had three, fixed in 4.2.1.
- certifi 2026.6.17 had one, fixed in 2026.10.19.

Pillow 13 requires FastEmbed 0.9.1. Measuring that upgrade
(`../architecture/benchmarks/2026-10-27-embedding-runtime-equivalence.md`) showed that the store's
behaviour fingerprint changes with the ONNX Runtime release while behaviour does not: cosine
1.000000 and identical retrieval metrics. Published releases therefore refused to open stores after
routine dependency updates, and silently ran without the certified relevance filter.

With the owner's approval (AD-055), compatibility and the certified default are now judged by
behaviour, with measured-equivalent fingerprints accepted. The dependencies were moved and pip-audit
is clean. `scripts/verify_release.py` then passed on commit `885316c`. It covered:

- clean `main`, lock, pytest, Ruff;
- dashboard lint and rendered-HTML test, and the production dashboard audit;
- pip-audit;
- two byte-identical builds and the Twine check;
- Gitleaks over the tree, full history, and artifacts.

Separately recorded and not fixed in this release: the `all-MiniLM-L6-v2` certification from July
no longer matches today's model download, so that model needs re-certification.

## Release verification

- **Clean installs.** The built wheel, installed fresh with ONNX Runtime 1.31.1 as a new user
  receives it, completed an offline lifecycle on CPython 3.11.15, 3.12.11, 3.13.3, and 3.14.5:
  `occurred_at`, hybrid recall, re-ranked recall, and verified forget, with integrity `ok`.
  bge-small received the certified relevance filter on every version. `llm-memory --help`
  succeeded, and `llm-memory-mcp` started and exited cleanly on end of input.
- **Older store, real model.** A store created by the published 0.3.0 (FastEmbed 0.9.1, ONNX
  Runtime 1.31.1), which runs there with the filter off, opened under 0.4.0 with the certified
  filter on.
- **Re-ranking unchanged.** On the tuning pool under the new locked runtime, re-ranking reproduces
  its tuning result: vector 121/174, re-ranked 138/174.
- **Reproducible from the tag.** A fresh clone of the public GitHub tag rebuilt byte-identical
  artifacts.
