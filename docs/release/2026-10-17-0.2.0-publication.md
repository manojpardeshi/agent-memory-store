## Pre-publication gate

`scripts/verify_release.py` passed on the release commit: clean `main`, lock, pytest, Ruff, dashboard
lint and rendered-HTML test, production dashboard audit, pip-audit, two byte-identical builds, Twine
check, and Gitleaks over the tree, full history, and artifacts.

Changes needed to pass it, each its own commit:

- **Runtime advisories.** pip-audit flagged `mcp` 1.28.1, `pyjwt` 2.13.0, `cryptography` 49.0.0, and
  `urllib3` 2.7.0. The lock moved to 1.30.0, 2.15.1, 50.0.2, and 2.8.0, and the minimum `mcp` rose to
  1.30.
- **Build backend.** `hatchling` 1.32 writes Metadata 2.5, which Twine 6.2.0 rejects. It is pinned to
  1.31.0, which built the published 0.1.0 wheel.
- **Gitleaks allowlist.** Benchmark evidence records SHA-256 digests of human-audit answer-key files
  in fields named `key`. A narrow allowlist accepts only that field name with a 64-hex value in
  benchmark JSON. A planted credential in the same files is still reported.
- **Dashboard audit.** Owner decision, 2026-10-17: the gate audits the demo dashboard's production
  dependencies only, which have no findings after updating `next` (a critical advisory), `wrangler`,
  and related packages. These high-severity development-tool findings remain:
  - `braces` GHSA-vfj7-8cjw-p6xm (all versions ≤ 3.0.3; no patched release). It reaches
    `micromatch`, `fast-glob`, `@next/eslint-plugin-next`, `eslint-config-next`,
    `vite-plugin-dynamic-import`, `vite-plugin-commonjs`, and `vinext`.
  - `image-size` GHSA-5p2g-fcmc-qvqq and GHSA-w3rx-r6r6-pgpr through `vinext` 0.0.50. These are
    fixed only in `vinext` 1.x, whose `cloudflare:` imports break the dashboard's Node rendered-HTML
    test.

  None of the dashboard is in the Python package.

## Release verification

- A clean install of the built wheel completed an offline lifecycle on CPython 3.11.15, 3.12.11,
  3.13.3, and 3.14.5: remember, vector and hybrid recall, metadata lookup, verified forget, keyword
  index `ok`, and integrity `ok`. `llm-memory --help` succeeded on each, and `llm-memory-mcp` started
  and exited cleanly on end of input.
- Compatibility with `llm-memory-store==0.1.0` from PyPI:
  - 0.1.0 wrote to and forgot from a 0.2-indexed store with the index consistent: the forgotten
    term was gone and the 0.1-written memory was found by hybrid recall.
  - 0.2 backfilled the index of a store created by 0.1.0 (2 of 2 memories indexed).
- A fresh clone of the public tag rebuilt byte-identical wheel and source archive.

## Forge change

The Codeberg release was not created. While preparing it, Codeberg's new Terms of Use §2(1)7 came to
light: it prohibits projects mostly written by generative-AI tools such as Claude and OpenAI Codex.
The repository moved to GitHub (AD-054), with history, branches, and the `v0.1.0` and `v0.2.0` tags
intact. GitHub releases were created for both versions:

- **0.2.0** carries the verified artifacts above.
- **0.1.0** carries the files downloaded from PyPI and checked against the 0.1.0 publication record.

The 0.2.0 package metadata on PyPI still lists the Codeberg URLs, because PyPI metadata is immutable
per version; the next release carries the GitHub URLs.
