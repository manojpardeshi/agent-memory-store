# Publication Privacy Audit

Date: 2026-07-22
Status: content discovery complete; clean-publication decision executed; private history remains blocked

## Decision

Do not make the existing repository history public. Every one of the 17 reachable commits carries
the same non-noreply Gmail address in its author and committer metadata. File-content scanning did
not find credentials, personal memory artifacts, local paths, or email addresses, but publishing
this Git history would expose that address permanently.

The owner created `https://codeberg.org/manojpardeshi/agent-memory-store` from the reviewed clean
tree with `manojpardeshi@noreply.codeberg.org` as the author and committer identity. Rewriting and
force-pushing this private repository is not part of this audit.

## Scope and method

- All refs and all reachable history: 17 commits and 272 unique blobs.
- Current tracked tree, exported with `git archive HEAD`; ignored build products and local caches
  were not treated as publication inputs.
- Gitleaks 8.30.1 using the maintained default rules plus `.gitleaks.toml`.
- Gitleaks release archive:
  `gitleaks_8.30.1_darwin_arm64.tar.gz`.
- Verified release-archive SHA-256:
  `b40ab0ae55c505963e365f271a8d3846efbc170aa17f2607f13df610a9aeb6a5`.
- Archive traversal depth: two; recursive decoding used the scanner default.
- Independent Git-object inspection for risky filenames, SQLite headers, private-key markers,
  absolute home paths, `file://` attachment paths, email addresses, and owner-name occurrences.
- Manual source review of default diagnostics and the versioned evaluation-corpus provenance.

The reproducible history command, after installing the verified binary, is:

```bash
gitleaks git \
  --config .gitleaks.toml \
  --log-opts='--all --full-history' \
  --max-archive-depth 2 \
  --redact=100 \
  --report-format json \
  --report-path OUTSIDE_REPOSITORY/history.json \
  .
```

The tracked-tree check exports `HEAD` into a temporary directory and runs `gitleaks dir` against
that directory with the same configuration, archive depth, redaction, and external report path.
Raw reports are sensitive audit inputs and are not committed.

The scanner initially reported six `generic-api-key` candidates in committed demo reports. Manual
review traced every candidate to deterministic synthetic data generated by the demo harness:

- `private_secret` values use the exact `PRIVATE-` plus six hexadecimal-character canary format.
- `consumer_key` values use the exact generated `consumer_<number>_<slug>` scope format.

The configuration allowlists only those two complete line shapes. It does not allow a file, commit,
general key name, or arbitrary value.

## Logging and diagnostic review

The package imports no logging framework and defines no background diagnostic sink. The CLI writes
requested structured operation results to stdout; those results are the command's explicit data
response, not diagnostic logging. Its default stderr progress message contains only the operation
name and completed/total counts. The MCP server writes tool protocol responses by design and adds no
custom content-bearing diagnostics. Reviewed validation errors describe fields, identifiers, state,
or paths rather than copying memory bodies, embeddings, prompts, model reasoning, or credentials.

Result: the default-logging portion of the release gate passes for the reviewed package source.
Applications embedding the Python API remain responsible for their own logging policy.

## Synthetic-fixture provenance review

All four versioned evaluation datasets declare synthetic provenance in their top-level description:

- `retrieval_v1.json`: synthetic and contains no user-derived data.
- `retrieval_v2.json`: independently Claude-authored synthetic domains and no user-derived data.
- `extraction_v1.json`: synthetic, judge-free, and contains no personal or production data.
- `extraction_v2.json`: independently seeded synthetic data and no owner data.

Their builder sources contain fictional projects, institutions, names, dates, identifiers, and
explicit negative controls. The history-wide checks found no email address, local home path, owner
name, database artifact, or attachment path in the evaluation files.

Result: technical provenance review passes. The project owner affirmed on 2026-07-22 that the
datasets were created synthetically and were not transformed from personal memories.

## Limitations and next gate

Automated scanning cannot prove the absence of paraphrased personal information, and a clean scan
does not replace review of publication artifacts produced later. The same scans must run against the
final clean publication tree and built wheel/source distribution before release.

Clean installation, package-content, supported-Python, checksum/SBOM, release-note, and final artifact
scans now pass. Public visibility remains blocked until the reviewed tree is imported into a clean
Codeberg history with a public/noreply identity, rescanned, and explicitly authorized for tagging and
publication.
