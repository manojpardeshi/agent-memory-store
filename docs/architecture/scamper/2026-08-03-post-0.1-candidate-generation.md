# SCAMPER Pass 001 — Post-0.1 Candidate Generation

Date: 2026-08-03
Status: ideation record. **No candidate here is frozen, contracted, or authorized to run.**
Method: `../scamper-methodology.md`

## Framing

Context bundling closed with no queued alternative. This pass sweeps the seven lenses
against the measured state to generate replacements. Each candidate is stated with the
evidence that motivates it, a falsifiable gate, and an honest cost. Candidates that the
evidence undercuts are recorded as undercut rather than quietly dropped.

The dominant, repeatedly measured fact governs everything below: **retrieval finds the
right session ~97% of the time and the answer is right ~78% of the time.** Roughly
nineteen points are lost after the evidence is already in the context window, concentrated
almost entirely in multi-session and temporal-reasoning.

---

## C1 — Query-time synthesis over retained raw messages
**Lens: Reverse** (invert ingest-time extraction to query-time)

Mem0 extracts at ingest and discards the source. Measured consequence: the gold answer
survives anywhere in its store for 11.7% of questions, and no retrieval improvement can
recover what was destroyed. This project already avoids that by retaining everything —
but it also therefore never gets extraction's benefit, and hands the reader raw messages
to compose unaided.

Invert the order. Keep raw ingestion exactly as it is, and perform extraction at query
time over the ten retrieved messages: condense them into a compact evidence set before the
reader sees them. Extraction errors become recoverable, because the source is still there
and the next query re-derives from scratch. A bad ingest-time extraction is permanent; a
bad query-time extraction is one query.

This is the lens's real yield: the failure mode that makes local extraction unusable at
ingest — irreversible loss — is largely neutralised by moving it to query time.

*Motivating evidence:* store 96.7% vs Mem0 13.3% content retention; the 97%→78% gap sits
exactly where this operates.
*Falsifiable gate:* on the frozen development split, answer accuracy improves by at least
three answers with no category losing more than one, at equal or fewer context tokens,
with zero change to stored data.
*Cost:* an LLM call per query, which introduces a per-recall model dependency the product
does not currently have. **This directly tensions the offline-core invariant** and must be
default-off and explicitly opt-in, or restricted to a local model, or both.
*Risk:* the same weak local model that fails at ingest may fail here. The difference is
that failure is no longer destructive — but it may still be unhelpful.

## C2 — Deterministic temporal index with no model in the path
**Lens: Eliminate** (remove the LLM from the failing category entirely)

Temporal-reasoning scores 5/10 while its retrieval succeeds at 0.858 answer-session
recall@10. The questions require date arithmetic — intervals, ordering, "how many days
until" — and the store already records source timestamps but never reasons over them. It
ranks by semantic similarity plus recency and hands the reader raw text.

Eliminate the model from this path. Parse dates and durations deterministically at ingest
into a queryable temporal index, detect temporal intent in the query, and supply computed
values alongside retrieved messages. The existing `DeterministicRuleExtractor` already
passes its 12-case offline track and needs no network, no weights, and no review workflow,
because rule output is auditable in a way model output is not.

This is the only candidate here immune to the local-extraction wall recorded in AD-038,
AD-039, and the Mem0 comparator, because it removes the dependency rather than managing it.

*Motivating evidence:* temporal 5/10 against 0.858 retrieval; four other categories at
39/40 combined.
*Falsifiable gate:* temporal-reasoning answers improve by at least three of ten with zero
regression elsewhere, no new network or model dependency, and full provenance retained.
*Cost:* date parsing is deceptively hard across the corpus's informal phrasings; coverage
must be measured before promotion, and low coverage is itself a valid negative result.

## C3 — Span-level context minification
**Lens: Modify** (change output granularity, which is fixed by habit not evidence)

The store returns whole messages. Inspection of the comparator run shows some retrieved
messages are very large — a full chocolate cake recipe occupied one of ten slots. Ten
slots of whole messages is a token budget spent largely on irrelevant text, and
result-precision@10 is 0.700 overall and 0.510 for preferences.

Return relevant spans rather than entire messages, so the same budget carries more
distinct evidence. Nothing is discarded from storage; this changes only what is projected
into the context.

*Motivating evidence:* precision@10 of 0.700; multi-session questions needing evidence
from several sessions competing for ten whole-message slots.
*Falsifiable gate:* mean context bytes fall at least 25% with answer accuracy not
regressing and multi-session not losing any answer.
*Cost:* span selection is itself a retrieval decision and can cut the answer-bearing
sentence. That is precisely how `session-diverse-v1` failed — by pruning the answer-bearing
message — so this candidate must carry an explicit no-answer-pruning check.

## C4 — Dual-layer memory: raw substrate plus derived index
**Lens: Combine** (two subsystems that have never been run together)

Review-first extraction and raw ingestion exist as separate, non-comparable tracks; the
contract states Track B "must never be merged with Track A results." As *evaluation
tracks* that separation is correct. As *product architecture* it may be a false choice.

Keep raw messages as the authoritative substrate and layer accepted extracted memories
above them as a navigational index that points back to sources rather than replacing them.
Extraction becomes additive, never lossy. Mem0's measured failure is not that it extracts;
it is that extraction *replaces* the source.

*Motivating evidence:* the comparator isolates destruction, not extraction, as the failure.
*Falsifiable gate:* not yet specifiable. Requires a retrieval policy over two layers that
does not double-count evidence, and no such policy is designed.
*Status:* **retained as direction, not candidate.** By the methodology's own rule, a
candidate without a falsifiable gate stays in the record until someone can state one.

## C5 — Lexical and vector hybrid retrieval
**Lens: Substitute** (swap the ranking mechanism)

The benchmark contract's decision rule already nominates SQLite FTS5/BM25 fusion for
"entity, identifier, number, or exact-phrase misses." SQLite ships FTS5, so the dependency
cost is near zero.

Recorded honestly: **the standing evidence undercuts this.** Retrieval is at 97.0% Hit@10
and the measured loss is downstream. A ranking improvement optimises a stage with roughly
three points of headroom, which is the same error that consumed the last two cycles. It is
cheap and principled, and it is aimed at the wrong stage.

*Status:* generated, retained, deprioritised. Revisit only if C1–C3 produce a residual
that is specifically attributable to ranking.

---

## C6 — Provenance DAG as a multi-session evidence chain
**Lens: Put to another use**

The provenance DAG exists to compute deletion blast radius. It is a graph of derivation
relationships that nothing at query time consults. Multi-session questions are exactly
compositional-evidence questions, which is the shape a graph traversal serves.

*Motivating evidence:* multi-session 3/10 despite 0.892 answer-session recall.
*Falsifiable gate:* unspecifiable today. Benchmark ingestion is raw turns with no derived
memories, so the DAG is empty during measurement — the structure this candidate would
exploit does not exist in the evaluated configuration.
*Status:* **recorded as a structural observation, not a candidate.** Becomes reachable
only if C4 populates a derived layer.

---

## C7 — Benchmark the extraction track as a diagnostic
**Lens: Adapt** (apply this repository's other track to the current question)

Track B has never been run against LongMemEval. The Mem0 comparator now provides an
external reference point for what ingest-time extraction costs. Running this project's own
review-first extractor over the same 60 questions would show whether its extraction loses
less than Mem0's, using the identical provenance-free scorer.

*Motivating evidence:* the comparator measured a competitor's extraction loss without ever
measuring this project's own.
*Falsifiable gate:* diagnostic only; no promotion. Reports content-retention rate under
the same criterion.
*Cost:* local-model inference hours, no paid calls. Cheapest informative run available.
*Status:* **strong diagnostic, weak product candidate.** It answers a question the project
should not be guessing at.

## Lenses that yielded little

**Substitute (embedder).** Swapping bge-small for a larger model is available and cheap,
but AD-036 certified the current identity through a paired matrix, retrieval is saturated,
and a new identity invalidates that certification and forces re-certification for a stage
with ~3 points of headroom. Cost exceeds plausible benefit.

**Reverse (answer-then-verify).** Generate a candidate answer, then retrieve to verify.
Coherent, and it doubles model calls per query in a product whose core is offline. The
offline-core invariant makes it structurally unattractive rather than merely expensive.

## Ranking

By dominant-failure targeting, cost, and consistency with standing evidence:

| Rank | Candidate | Targets | Blocking concern |
| ---: | --- | --- | --- |
| 1 | **C2** deterministic temporal index | temporal 5/10 | date-parse coverage unknown |
| 2 | **C7** extraction-track diagnostic | measurement gap | none; diagnostic only |
| 3 | **C1** query-time synthesis | the 97%→78% gap | tensions the offline invariant |
| 4 | **C3** span minification | context precision | answer-pruning risk |
| — | C4, C5, C6 | — | no falsifiable gate, or wrong stage |

C2 ranks first because it attacks a measured dominant failure while *removing* the
dependency that has now defeated two extraction systems, rather than managing it. C7 ranks
second on cost alone: it is the cheapest run that converts a guess into evidence.

## What this pass does not do

It authorizes nothing. C2 and C7 are the recommended next contracts, and each still
requires a frozen pre-registered contract, its own corpus discipline, and explicit owner
authorization before any measured run. Sealed validation and reserve remain unopened.
