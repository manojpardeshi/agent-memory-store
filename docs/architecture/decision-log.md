# Architecture Decision Log

This is the living index of material decisions. An entry is an implementation constraint only when its status is **Accepted**. Proposed entries require validation or product-owner approval.

Last updated: 2026-07-22

## Status Definitions

- **Proposed**: under discussion; not an implementation commitment.
- **Accepted**: approved and safe to use as an architectural constraint.
- **Rejected**: evaluated and intentionally not selected.
- **Superseded**: replaced by a later decision.

| AD-001 | Accepted | Require an explicit discovery gate before detailed architecture approval. | Users, requirements, constraints, scale, security, assumptions, success measures, and trade-offs must be documented before component design becomes a commitment. | Product boundary changes materially. |
| AD-002 | Accepted | Build a greenfield, personal, model-agnostic memory layer for LLM applications and agents. | The sole user wants durable context shared across providers, with no legacy system to preserve. Multi-user product concerns are intentionally excluded. | A second human user, external customer, or legacy integration enters scope. |
| AD-003 | Accepted | Make v1 local-first, offline-capable, and approximately zero recurring infrastructure cost. | Core commit and recall cannot depend on cloud services or paid APIs. This favors embedded libraries and local inference, and constrains packaging and model size. | Remote access or managed operations become a product requirement. |
| AD-004 | Accepted | Use one embedded datastore with a portable primary artifact; do not require a database server. | Personal scale does not justify PostgreSQL or distributed infrastructure. Backup must still use a consistent SQLite-aware mechanism when the database is live. | Scale or concurrency exceeds measured embedded-store limits. |
| AD-005 | Accepted | Expose MCP over stdio as the primary v1 integration surface, plus a thin Python API. | Stdio is local, process-scoped, and supported by the official MCP SDK. There is no network listener or authentication service. | HTTP or cross-machine access is requested. |
| AD-006 | Accepted | Use local, swappable embeddings with one comparable embedding space per store. | Retrieval must remain independent of the consuming chat model, and vectors from incompatible embedding models cannot be compared. Exact model and migration UX remain open. | A use case requires simultaneous vector spaces or remote embedding APIs. |
| AD-007 | Accepted | Model typed episodic, semantic, preference, and summary memories; reference rather than own documents. | Typed lifecycles and provenance fit personal memory, while avoiding expansion into a document/RAG platform. Procedural memory is deferred. | Document ingestion or learned workflows become primary use cases. |
| AD-008 | Accepted | Default to private agent/application scopes and make sharing explicit. | Cross-model reuse is needed without accidental cross-agent recall. Scope behavior must be testable before API approval. | Multi-user authorization or organization-level tenancy is introduced. |
| AD-009 | Accepted | Keep raw-turn commit cheap and synchronous; make extraction, summarization, and embedding pluggable without an always-on daemon. | Source data should survive optional inference failures and the system must work without a continuously running model. Processing-state and retry mechanics remain open. | User experience requires unattended eventual processing. |
| AD-010 | Accepted | Correct memories through versioned supersession and require provenance. | This preserves what the system knew and why, improves debugging, and avoids silent overwrites. It increases deletion and active-version complexity. | Storage growth or privacy expectations require history-free replacement. |
| AD-011 | Accepted | Use filesystem permissions and OS full-disk encryption as the v1 security boundary. | One trusted user on one trusted machine does not justify app encryption or an auth service. Recalled content still remains untrusted input to an LLM. | Network transport, shared OS accounts, external users, or regulated data enters scope. |
| AD-012 | Accepted | Use SQLite plus `sqlite-vec` for storage and exact vector search. | It satisfies the embedded, portable requirement and passed integration, deletion, backup/restore, and representative vector benchmarks. `sqlite-vec` is pre-v1, so its adapter and schema remain isolated behind the store API. | Benchmark regression, upstream instability, or packaging incompatibility. |
| AD-013 | Accepted | Use exact KNN rather than approximate indexing in v1. | A 20,000-vector, 384-dimension benchmark measured 12.98 ms p95 for top-20 partitioned KNN on the reference machine, well below the 200 ms target. Exact search is deterministic and avoids ANN tuning. | Representative p95 exceeds 100 ms, scope fan-out becomes large, or data grows beyond 100,000 active vectors. |
| AD-014 | Accepted | Treat the raw memory transaction as authoritative and record embedding-processing state separately. | The memory row commits as `pending`; embedding runs in a second transaction and transitions to `ready` or `failed`. This prevents inference failure from losing an acknowledged memory and permits explicit retry without a daemon. | The API requires raw-plus-vector all-or-nothing commits or unattended retry becomes mandatory. |
| AD-015 | Accepted | Develop privately through the first end-to-end security and packaging milestone, then publish the sanitized implementation under a permissive open-source license. | Public development can attract users and validate the local-first niche, but a memory product has an unusually high risk of committing personal fixtures, database files, prompts, paths, or secrets. Publication is gated on a deliberate security and privacy review. | The product owner chooses closed-source commercialization, or publication creates unacceptable privacy or maintenance risk. |
| AD-016 | Accepted | Use Codeberg as the canonical public source forge and PyPI as the Python distribution channel; use GitHub only as an optional read-only discovery mirror. | Codeberg's nonprofit, Free Software focus aligns with the project's local-first and user-control values. PyPI gives Python users a conventional installation path independent of the source forge. A GitHub mirror may improve discovery without making GitHub authoritative. | Codeberg cannot meet repository, CI, release, or availability needs; another package ecosystem becomes primary; or maintaining a mirror creates disproportionate work. |
| AD-017 | Accepted | Default to `BAAI/bge-small-en-v1.5` through FastEmbed, and bind every store to a behaviorally fingerprinted embedding identity. | The small local model gives a practical quality/size compromise and works offline after first download. Provider, model, revision, runtime, dimension, normalization, distance, and a sentinel-vector fingerprint prevent silently mixing incompatible vector spaces. | Quality evaluation fails, model licensing/distribution changes, or migration to a new model is requested. |
| AD-018 | Accepted | Represent access boundaries as normalized, exact-match private or explicitly shared scopes and represent derivation as a provenance DAG. | This makes cross-agent sharing deliberate and deletion impact computable. Wildcard and hierarchical scope reads are excluded from the MVP. Provenance edges are cycle-checked. | Hierarchical projects, multiple human users, or policy-based authorization enters scope. |
| AD-019 | Accepted | Define hard delete as transactional removal of the selected lineage and all recursively derived descendants from the active database. | A preview exposes the blast radius; vectors and provenance edges are removed with rows and the result is verified. Deleting a derived memory does not delete its source. This is logical erasure from the active store, not a forensic guarantee for filesystem snapshots or storage media. | Regulated or forensic erasure, remote replicas, or shared-user retention rules enter scope. |
| AD-020 | Accepted | Let callers create typed memories directly in the MVP; defer automatic LLM extraction and summarization. | Direct typed writes are deterministic, model-neutral, offline, and testable. The processing-state design leaves room for a future extractor without making a local generative model an MVP dependency. | User testing shows manual/caller-created memories are insufficient for useful continuity. |
| AD-021 | Accepted | Give raw turns a configurable 30-day default TTL and keep typed memories until explicitly corrected, expired, or deleted. | This limits routine transcript retention while preserving curated knowledge. Expired rows are excluded from recall lazily; automatic physical purge is intentionally not claimed in the MVP. | Disk retention expectations require scheduled physical purge or different type-specific policies. |
| AD-022 | Accepted | Treat export, backup, and restore as sensitive artifact operations with explicit selection, confirmation at the MCP boundary, owner-only creation, and no overwrite by default. | Memory portability must not become a store-wide exfiltration or arbitrary-file-clobber primitive. Restore only creates a new destination and never manipulates a potentially live destination's WAL/SHM files. | A trusted interactive UI supplies stronger OS-native consent or remote artifact storage is introduced. |
| AD-023 | Accepted | Validate model switching with two explicitly separated tracks: a deterministic offline gate and a manual live-model evidence run where the harness owns memory operations. | This proves store orchestration and model context consumption without conflating autonomous tool selection, hosted-model availability, or general retrieval quality. Demo thresholds apply only to randomized synthetic slots; live latency is non-gating telemetry. | Autonomous agent tool use or cross-vendor continuity becomes the claim under evaluation. |
| AD-024 | Accepted | Demonstrate switching in a local evidence dashboard and quantify every context handoff with exact item, character, and UTF-8 byte counts plus a clearly labeled characters/4 token estimate. | A replayable report keeps the UI deterministic, private, and auditable. The browser does not receive the SQLite store or invoke hosted models. Estimated tokens are useful for comparison but are not provider billing data or exact tokenizer output. | Exact provider tokenizer/cost accounting or direct UI-triggered live runs become a requirement. |
| AD-025 | Superseded | Replace the two-model demo assumption with a provider-neutral producer/consumer matrix supporting Claude CLI, hosted GPT through ephemeral Codex CLI, and future local models through Codex OSS mode with Ollama or LM Studio. | The consumer matrix remains accepted, but AD-026 replaces Codex OSS as the measured Ollama transport after the installed Qwen model emitted Codex tool-wrapper syntax instead of the requested JSON. | N/A; superseded by AD-026. |
| AD-026 | Accepted | Keep hosted GPT behind Codex CLI, but measure local Ollama models through the loopback Ollama JSON API with structured output and native token counters. | Direct Ollama JSON avoids Codex agent/tool prompt interference observed with `qwen2.5:7b`, preserves fresh stateless calls, and exposes prompt/output token counts. The endpoint must be loopback-only by default; arbitrary remote Ollama hosts are outside the personal-demo security boundary. | Codex OSS becomes reliably compatible with the selected model, LM Studio is installed, a remote model host is requested, or tool-use behavior becomes part of the evaluation. |
| AD-027 | Accepted | Use `llama3.1:8b` as the MVP's selected local-model evidence target while keeping the Ollama adapter model-configurable. | The user identified this as the intended local model, and the installed 8.0B Q4_K_M build completed the full real matrix with 0/3 baseline slots and 3/3 memory-assisted slots correct, plus zero scope violations. The evidence pins content digest `46e0c10c...ca666e`; the tag alone is mutable. | The owner selects another target, the pinned build changes, or multi-model local comparison becomes an explicit benchmark requirement. |
| AD-028 | Accepted | Make a versioned synthetic retrieval-quality gate with irrelevant-memory and inaccessible-scope controls the next product slice and a prerequisite for retrieval-affecting features. | OQ-009 is the explicit public-release blocker. Automatic extraction or embedding migration without a quality baseline could silently degrade recall. A local dependency-free harness preserves the offline boundary and makes failures observable before tuning. | The evaluation corpus no longer represents real usage, metrics prove misleading, or a broader benchmark methodology is approved. |
| AD-029 | Accepted | Set retrieval-v1 gates to Recall@5 ≥ 0.90, MRR ≥ 0.85, designated distractor leakage ≤ 0.10, zero inaccessible-scope results, at least 50 queries with every memory type represented, and runtime ≤ 60 seconds. | Recall/MRR floors preserve margin below the measured 0.98 baseline; zero scope leakage is invariant. The distractor ceiling is a normative context-quality target, not baseline calibration: measured leakage is 0.24 versus a 0.40 uniform-random floor, so the model beats chance but does not yet meet the conservative relevance target. | Repeated representative corpora justify different thresholds, top-K changes, or the distractor control is shown not to predict irrelevant context exposure. |
| AD-030 | Superseded | Add relative semantic-gap filtering as an explicit opt-in across Python, CLI, MCP, and evaluation, with 0.20 as the documented candidate; preserve unfiltered default recall. | On retrieval-v1, relative 0.20 reduced distractor leakage from 0.24 to 0.06 without reducing 0.98 recall/MRR. One corpus/model was insufficient for a breaking default. AD-036 records the completed revisit evidence and identity-scoped default. | Superseded by AD-036. |
| AD-031 | Accepted | Make physical expiry purge an explicit cutoff-based preview/confirm operation that deletes only expired rows whose lineage-and-descendant deletion closure contains no unexpired memory. | Routine retention lacks the authority of explicit hard deletion. Cascading from an expired raw source could prematurely destroy a durable summary; deleting only the source would orphan provenance. Safe candidates are deleted atomically while blocked expired rows and their live blockers are reported. Execution recomputes under an immediate transaction, supports an optional preview digest, verifies rows/vectors/edges, and adds no scheduler. It may proceed while the retrieval gate is red because it cannot change recall ranking or exposure. | Tombstone/redaction semantics are accepted; blocked payload retention becomes unacceptable; multi-writer operation enters scope; or purge performance exceeds personal-scale targets. |
| AD-032 | Accepted | Migrate embedding models only by snapshotting the validated source and atomically publishing a verified new destination; expose Python and CLI but defer MCP. | In-place re-embedding risks mixed vector spaces and removes immediate rollback. A stable snapshot avoids holding the source during model inference. Structural equivalence and target identity are verified separately from synthetic retrieval quality. Source-to-target regression blocks by default on both default and opt-in-filter configurations; the pre-existing absolute default failure remains reported rather than laundered. MCP adds path, prompt-injection, and resource-exhaustion risk for little personal-scale benefit. | Multi-user coordination, remote embedding, accepted in-place recovery design, a stronger MCP consent mechanism, or broader quality evidence enters scope. |
| AD-033 | Accepted | Make JSON format v2 a hash-verified, operation-ID-preserving interchange format and import only into an atomically published new compatible store; support explicit v1 migration and defer MCP/merge. | V1 cannot preserve operation idempotency and partial exports can reference sources outside their selection. V2 adds content hashes and operation IDs and declares external references without widening disclosure. Import validates collisions, correction/provenance DAGs, generations, manifest compatibility, and input bounds, then regenerates vectors. Missing sources reject by default; explicit loss is receipted. New-destination Python/CLI avoids live-store conflict and agent-triggered path risk. | Existing-store merge, tombstones, dependency-closure export, streaming scale, schema v2 database changes, or stronger MCP consent enters scope. |
| AD-034 | Accepted | Provide a framework-free real-application starter with one orchestrator, interchangeable direct-Python/MCP memory clients, and deterministic-offline/loopback-Ollama model adapters; keep all memory operations application-owned. | Developers need an end-to-end integration pattern beyond evaluation harnesses. Recall-before-call, bounded untrusted context injection, post-success raw capture, explicit curation/correction, and preview-confirm deletion demonstrate the real contract without conflating model tool choice. Normalized deterministic parity gates both transports; live Llama remains informational. | Autonomous tool use, streaming, remote models, multi-user access, production UI, or user evidence requires a broader SDK. |
| AD-035 | Accepted | Make extraction a two-phase, content-addressed proposal workflow: explicit active sources produce an owner-only tamper-evident artifact, and only selected, revalidated proposals can become typed memories through idempotent Python/CLI acceptance; defer MCP. | Local model output is untrusted and cannot silently acquire durable-memory authority. Proposal IDs preserve reproducibility while a separate bundle digest binds review to the exact artifact. Whole-source staleness, strict response validation, loopback-only Ollama, and preflight before writes keep failure safe without a daemon or database schema change. MCP digest echo does not prove human consent. | A trusted host-mediated MCP approval mechanism exists; managed review queues are required; source-edit ergonomics justify span anchoring; or validated retrieval evidence permits automated duplicate/conflict policy. |
| AD-036 | Accepted | Make relative semantic-gap 0.20 the default recall policy only for the certified BGE-small-v1.5 and all-MiniLM-L6-v2 embedding identities; preserve explicit unfiltered opt-out and leave unknown models unfiltered. | A frozen 2-corpus × 2-model paired matrix reduced designated distractor leakage from 0.24/0.183/0.40/0.167 to 0.06/0.10/0.06/0.05 with no Recall@5 or MRR change and zero scope violations. The default may return zero to K items, a breaking cardinality change. Model scoping avoids treating two bi-encoders as universal evidence. | Any approved corpus exceeds its leakage ceiling, Recall@5 or MRR regresses by more than 0.02, a scope violation occurs, user evidence shows harmful missing recall, or a new embedding identity is selected. |
| AD-037 | Accepted | Evaluate extraction with a frozen two-track synthetic corpus and deterministic anchor/fact-unit scoring; make forbidden extraction and any write/source mutation hard failures, and keep live Llama results diagnostic. | Proposal validation proves structural safety but not completeness or over-extraction. Judge-free anchors, exact kind/provenance, negative cases, and Wilson intervals provide reproducible engineering evidence without adding an embedding or LLM judge. The initial 50-case live sample cannot support population claims, and passing never authorizes automatic acceptance. | Anchor audit shows systematic false negatives; a 100+ multi-author corpus is approved; another judge can be certified independently; or automation/managed review becomes a product requirement. |
| AD-038 | Accepted | Retain extraction-v2 as the conservative `llama3.1:8b` prompt, with explicit negative rules and one structured-output retry; reject v3 and defer a dedicated summary pass. | On the unchanged 50-case corpus, v2 reduced forbidden proposals and invalid cases from 4/4 to 0/0 but failed precision/recall/summary targets at 0.50/0.25/0.30. V3 restored facts but worsened precision to 0.367 and still produced no exact summaries. Safety and review load take priority while model output remains review-only; repeated prompt tuning would overfit one corpus. | A new multi-author corpus, dedicated-pass design, or stronger local model passes the same safety invariants and materially improves precision, recall, and summary coverage. |
| AD-039 | Rejected | Compare the preserved single-pass extractor with a dedicated atomic-plus-summary two-pass extractor on a new 50-case, two-author frozen corpus; do not expose the two-pass implementation. | The two-pass run improved summary coverage from 0.25 to 0.60 but reduced precision from 0.765 to 0.255, reduced recall from 0.325 to 0.300, introduced one forbidden and one invalid case, and nearly tripled runtime. Qwen 2.5 and compatible Qwen3 single-pass fallbacks also failed. Failed architecture code was removed; reports remain. | A materially different design and newly approved corpus show zero safety failures plus both absolute and paired quality gates. |
| AD-040 | Accepted | Send `think: false` to Ollama generate requests and accept an optional bounded string `thinking` response field while parsing and persisting only `response`. | Ollama 0.32.1 and Qwen3 returned the documented thinking field, causing all cases to fail strict envelope validation. The entire envelope retains the existing 1 MB bound; reasoning text is ignored and never enters proposal artifacts or evaluation reports. Unknown fields and non-string thinking values still fail closed. | Ollama removes or renames the field, cannot disable reasoning for a selected model, or trace handling becomes an explicit audited product requirement. |
| AD-041 | Accepted | Make proposal review a store-aware, read-only deterministic evidence step: revalidate exact source snapshots, classify durable replay/operation collisions, report normalized-content duplicates within the store and bundle plus identical-content/different-kind collisions only within the exact target scope, hide content by default, and keep acceptance separately digest-bound and explicit. | Every measured local extractor remains below automation gates, so review safety and speed matter more than further prompt tuning. Multi-axis evidence prevents duplicate/replay signals from hiding stale provenance. Exact comparison adds no model authority and preserves AD-018 scope semantics; it intentionally cannot detect paraphrases or semantic contradictions. CLI review enforces non-mutation with a SQLite read-only/query-only connection, and reusable preflight blocks invalid replay state before writes. The static dashboard can select from a report but cannot access SQLite or accept memory. A synthetic 100,001-row exact-scope run completed in 1.110 seconds with no database changes. | Structured memory keys or a separately certified semantic judge are approved; a persistent adjudication queue, multi-user review, hierarchical scope policy, browser-side acceptance, or review latency above two seconds at 100,000 active rows becomes a requirement. |
| AD-042 | Accepted | License the project under Apache-2.0, accept contributions under section 5 without a separate CLA, and provide best-effort community support with private-first vulnerability coordination. | The locked Python runtime closure is permissively licensed or otherwise compatible with separate Apache-2.0 project distribution; dashboard dependencies are not bundled into the Python wheel. Apache-2.0 preserves permissive use while adding an explicit patent grant. Public Forgejo issues cannot safely carry vulnerability details, so reporters first request a private channel without disclosure. | A dependency is vendored, a compiled dashboard is distributed, dependency terms change, a foundation requires different contribution governance, or a reliable dedicated security channel is established. |
| AD-043 | Accepted | Publish from a reviewed clean tree with a public/noreply Git identity rather than exposing the private development history. | Full-history and prospective-tree Gitleaks scans have zero unresolved content findings, logging defaults passed review, and the owner affirmed synthetic fixture provenance. However, all 17 private commits contain a non-noreply personal email in author and committer metadata. A clean public history follows the existing release gate without rewriting or force-pushing the private repository. | The owner explicitly chooses to publish the historical identity, Codeberg supplies a safe history-import mechanism that removes private metadata, or publication moves to another canonical forge. |
| AD-044 | Accepted | Release a minimal Python wheel and source distribution with Apache-2.0 metadata, CycloneDX 1.6 SBOM, SHA-256 manifest, Twine validation, locked-dependency vulnerability audit, and clean-wheel lifecycle evidence on CPython 3.11 through 3.14. | The broad development repository is useful for evidence but does not belong in a Python source archive. The final candidate sdist contains 21 package/policy members rather than tests, demos, dashboards, evaluation reports, or internal reviews. Wheel installs on four supported Python minors completed commit, recall, correction, export, backup, deletion, restore, and integrity checks with network-disabled deterministic runtime. | A supported Python minor fails, compiled/native project code is added, the dashboard becomes a separately distributed artifact, PyPI metadata requirements change, or the dependency/audit format is replaced. |

## Verified Dependency Notes

These are observations, not component decisions:

- On 2026-07-15, the locked MVP environment uses `sqlite-vec` 0.1.9, FastEmbed 0.8.0, and MCP 1.28.1.
- `sqlite-vec` is explicitly pre-v1; breaking changes are an acknowledged risk.
- Its stable feature set supports exact KNN. Experimental ANN work is not required for the expected scale.
- The official MCP Python SDK supports stdio transport.
